# 图片载波接收首版：沿用现有 FPGA 数据链

## 当前交付与验收边界

新增 `image` / `img` 页面，底栏“图片”；原“系统”仍为数字页号 5，图片为 6。
图片像素只来自实际解调器的符号回调，生产界面没有预置测试图片，也不读取电脑端原图作为接收结果。
原始波形、调制分析页与三档本地窗函数保留。图片功能不要求修改 FPGA RTL 或换 bit。

已通过本机软件验证：OOK、2FSK、BPSK 生产 DSP → Manchester → 包 CRC → 图块 → 整图 CRC；
BPSK 还覆盖两种相位及 80Hz 载波偏差。测试数据是合成基带，不能宣称已经完成发生器→ADC→屏幕的实机图片传输。
QPSK 尚无生产符号/bit 恢复链，不列入本版图片制式。

发生器 UTG2062X 实际只读核查仍为 CH2：1MHz SIN、0.3333333Vpp、内部 SIN 1kHz、50% AM。
未改变该输出。自定义调制文件需要厂商 `.bsv` 格式及正确传输/导入；CSV 改扩展名不等于 BSV。
内置 PN7 只能发送固定伪随机序列，不能用它冒充图片载荷。

## 使用流程

1. 连接仍为发生器 CH2 → FPGA ADC CH0（屏幕 CH1）；UART 沿用 AA5/AB5。
2. 进入“图片”，点 OOK、2FSK 或 BPSK。该操作显式选择分析模式、标准抽取档与 1000Bd，关闭参考码型比对。
3. 控制条可改通道/符号率；“对频”使用本通道的新鲜测量。载波参考仍应与实际发生器一致。
4. 等待分包。灰块表示尚未收到，不算解码成功；包 CRC 通过才画入该块。
5. 全部图块及整图 CRC 均通过才显示 `CRC OK · 图已接收`。
6. 链路中断仅丢弃当前未完成的包，已校验图块保留；重复发送补齐缺块。`Last packet` 单独反映处理的新鲜度，旧图不能冒充新的接收。
7. “复位”清空图片与同步状态。原有“解码 开/关”控制判决；切回调制页仍可观察实际波形。

当前解调及队列处理随调制/图片页面运行；其他页面停留过久可能发生队列丢帧，返回后靠重复包恢复。
本版不承诺后台持续通信，不将 CRC 错包数解释成真实 BER。

## V32IMG1! 图片载荷协议（非 FPGA 串口帧族）

这是载波中的数据格式；它在现有 `V32ANA1!` 样本被解调成符号后恢复，不是把图片通过 UART 绕过 ADC 发送。
所有多字节整数小端；线上字节按 MSB-first，Manchester：0→01，1→10。
1000Bd 为物理符号率，编码后 500bit/s，尚未扣包头及训练开销。

每个包先发 32 字节 `0x55` 训练前缀（512 个 Manchester 符号），再发固定 68 字节：

| 字节偏移 | 内容 |
|---|---|
| 0..7 | ASCII `V32IMG1!` |
| 8 | 版本 1 |
| 9 | 格式 1：黑白，逐行，MSB 为左边像素，1 为黑 |
| 10..11 / 12..13 | 宽 / 高，各 1..128 |
| 14..15 | 图块长度固定 32 字节 |
| 16..19 | image_id，发送会话标识 |
| 20..23 | 完整图像像素字节的 CRC32 |
| 24..27 | 总字节数 `ceil(width/8)*height`，最多 2048 |
| 28..29 | 图块序号，从 0 开始 |
| 30..31 | 当前有效载荷长度，最后一包可不足 32 |
| 32..63 | 像素字节；最后一包尾部填 0 |
| 64..67 | 对前 64 字节计算 CRC32/IEEE，反射多项式 0xEDB88320，与 zlib.crc32 一致 |

接收器同时检索两个 Manchester 配对相位及同步字的正/反极性，处理任意启动位置及 BPSK 180°歧义。
尺寸、字节数、序号、长度、同会话元数据都检查后再写数组；固定内存，无网络原图替代路径。

## 生成与发生器适配

```sh
python3 tools/make_image_demo.py --out /tmp/image_tx
# 可选：--pbm /path/input.pbm，二进制 PBM/P4，最大 128×128
```

默认 32×32、128 字节、4 包。生成真实 `image.raw`、`packets.bin`、`symbols.bin`、PBM 和调制包络 CSV。
CSV 每符号保持 8 个采样点，51200 点覆盖 6400 符号；1000Bd 时一轮 6.4 秒，调制 ARB 的**整轮频率是 0.15625Hz**，不能误设为 1000Hz。
该时长只是无丢包、成功捕获全部包的理想单轮长度，不是实测接收时长。

待验证的发生器路径为：

- OOK：自定义 ARB 为 ±1，AM 深度 100%，两种包络幅度对应关/开。若保持峰值不高于既有 0.3333333Vpp，应使用约 0.1666667Vpp 的 AM 基准幅度；需实测核验幅度定义。
- 2FSK：同一包络作为 FM 调制源，偏移 ±1kHz，FPGA 选 mode=3，载波中心仍为 1MHz。
- BPSK：同一包络作为 PM 调制源，±90°产生 180°差，FPGA 选 mode=6；极性由同步字消歧。

这些是依据厂商任意调制功能设计的路径，**尚未完成本机 BSV 导入/实机验收**。不要仅设置内置方波/PN7 然后宣称传输了本图片。

官方手册：<https://storage.googleapis.com/uni-tdocuments/Library/UTG2000X%20Series%20Waveform%20Generators%20-%20Programming%20Manual.pdf>
相关命令为 `WARB<n>:MODulate`、`CHANnel<n>:MODulate:ARB`、`FM:FREQuency:DEV`、`PM:PHASe:DEV`。
