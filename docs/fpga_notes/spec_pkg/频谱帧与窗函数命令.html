AB5 第三帧：频谱帧 V32SPEC! + 窗函数命令 + 2 Mbaud

面向：FPGA 采集板
目标：把 8192 点 FFT 的频谱结果发给主机显示；窗函数可由主机远程切换；波特率提到 2 Mbaud
现有两帧（波形 V32CAP3! / 锁相 V32MEAS!）格式完全不动

一、本次要做四件事

#改动谁做
1串口 921600 → 2 MbaudFPGA + 主机
2新增 频谱帧 V32SPEC!（8192 点 FFT，4096 bin，每 bin 1 字节）FPGA 发 / 主机收
3新增 窗函数命令（主机 → FPGA，0xA6 w）主机发 / FPGA 收
4发送顺序固定为 波形 → 锁相 → 频谱FPGA

二、为什么必须把波特率提到 2 Mbaud

三帧一组，频谱帧 4096 bin 时整组 8412 字节：

波特率一组字节组/秒说明
921600（现在）841211.0波形都卡了，不可接受
2 Mbaud841223.8波形和频谱都流畅
2 Mbaud（bins=2048）636431.4更省，但频谱分辨率减半

2 Mbaud 8N1 = 200,000 B/s，是这个方案的最低要求。

三、一组数据的结构

┌────────────────┬──────────────┬────────────────┐
│ 波形帧 4140 B  │ 锁相帧 128 B │ 频谱帧 4144 B  │  共 8412 B
│  V32CAP3!      │  V32MEAS!    │  V32SPEC!      │
└────────────────┴──────────────┴────────────────┘

三帧各自独立 CRC32，任一 CRC 错则该帧作废，不影响其它两帧。

频谱帧用 wave_frame_id 关联到同组的波形帧（和锁相帧的做法一样）。

⚠️ 频谱帧对应的 FFT 应当与分析窗口是同一段采集（至少紧邻），
否则屏幕上「波形」和「频谱」对不上，用户会以为仪器坏了。

四、频谱帧 V32SPEC! 格式

偏移长度字段类型取值 / 说明
08magicchar[8]V32SPEC!（56 33 32 53 50 45 43 21）
84versionu321
124lengthu32整帧字节数 = 44 + bins + 4
164wave_frame_idu32关联的波形帧 frame_id
204result_idu32结果序号，每帧 +1
244nfftu32FFT 点数，8192
284binsu32本帧携带的 bin 数，4096（正频率半边）
324fs_eff_hzu32等效采样率 = 65000000 / decimation
364windowu320=Hann 1=Blackman 2=Flat Top（实际用的窗，回报给主机）
404scale_dbfsu32幅度标度，120（见第五节）
44binsspectrumu8[bins]bin 0..bins-1，每 bin 1 字节
44+bins4crc32u32覆盖前面全部字节（不含自己）

bins = 4096 时整帧 4144 字节。

bin 序号与频率的对应

f(k) = k × fs_eff_hz / nfft        （k = bin 序号）

例：fs_eff = 65 MHz、nfft = 8192 → 每个 bin = 7.9346 kHz，

bin 3781 ≈ 30.00 MHz。

五、幅度编码（每 bin 1 字节）

byte = round( (dBFS + scale_dbfs) / scale_dbfs × 255 )      钳位到 0..255
dBFS = byte / 255 × scale_dbfs - scale_dbfs
  • scale_dbfs = 120 → 0 = −120 dBFS，255 = 0 dBFS，分辨率 0.47 dB
  • dBFS 参考与现有实现一致：满刻度 2048 码（peak）= 0 dBFS

```

dBFS = 20 × log10( 幅度码 / 2048 )

```

为什么只用 1 字节：屏幕一格才几个像素，0.47 dB 已经远超显示需要；
用 2 字节会让整组变成 12460 B、帧率掉到 16 组/秒。

六、窗函数命令（主机 → FPGA）

复用现有的反向通道（主机 TX → FPGA RX）。命令固定 2 字节：

命令含义
0xA5, k抽取倍数 = 2^k（k=0..8）——已有
0xA6, w窗函数 w：0=Hann，1=Blackman，2=Flat Top ——新增

FPGA 收到 0xA6 后，把下一次 FFT 的窗换掉，并在后续频谱帧的

window 字段里填实际使用的窗（主机靠这个字段确认生效）。

默认上电用 Hann（与现有片上找频一致）。

七、验收标准

  1. 回归：波形帧、锁相帧格式和现在完全一致（偏移、长度、CRC 都不变）。
  2. 帧率：2 Mbaud 下三帧连续发送，主机实测 ≥ 22 组/秒。
  3. 频谱正确性：输入 30 MHz、1 Vpp 正弦，
  • 频谱帧里 bin 3781 应是最大值
  • 该 bin 的 dBFS 与主机示波器读到的幅度能对上（±1 dB 内）
  1. 窗函数：主机发 A6 01（Blackman）后，

后续频谱帧 window 字段应变成 1，且主瓣明显变宽（这是窗生效的证据）。

  1. 关联：频谱帧的 wave_frame_id 必须等于同组波形帧的 frame_id。

九、自检

python check_v32_frame.py 抓包.bin

会逐帧打印类型、关键字段、CRC 和频谱峰值位置：

[V32CAP3!] fid=1001 pts=1024 CRC OK
[V32MEAS!] wid=1001 usable=1 amp1=300.0 counts pdiff=21.97° CRC OK
[V32SPEC!] wid=1001 nfft=8192 bins=4096 win=Blackman 峰值 bin 3781 = 30.00 MHz CRC OK

跑不出这三行，就说明还有问题。
