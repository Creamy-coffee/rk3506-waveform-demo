# AB5 第三帧：频谱帧 V32SPEC! + 窗函数命令 + 2 Mbaud

> 面向：FPGA 采集板
> 目标：把 **8192 点 FFT 的频谱结果**发给主机显示；窗函数可由主机远程切换；波特率提到 2 Mbaud
> 现有两帧（波形 V32CAP3! / 锁相 V32MEAS!）**格式完全不动**

---

## 一、本次要做四件事

| # | 改动 | 谁做 |
|---|---|---|
| 1 | 串口 **921600 → 2 Mbaud** | FPGA + 主机 |
| 2 | 新增 **频谱帧 `V32SPEC!`**（8192 点 FFT，4096 bin，每 bin 1 字节） | FPGA 发 / 主机收 |
| 3 | 新增 **窗函数命令**（主机 → FPGA，`0xA6 w`） | 主机发 / FPGA 收 |
| 4 | 发送顺序固定为 **波形 → 锁相 → 频谱** | FPGA |

---

## 二、为什么必须把波特率提到 2 Mbaud

三帧一组，频谱帧 4096 bin 时整组 **8412 字节**：

| 波特率 | 一组字节 | 组/秒 | 说明 |
|---|---|---|---|
| 921600（现在） | 8412 | **11.0** | 波形都卡了，不可接受 |
| **2 Mbaud** | 8412 | **23.8** | 波形和频谱都流畅 |
| 2 Mbaud（bins=2048） | 6364 | 31.4 | 更省，但频谱分辨率减半 |

**2 Mbaud 8N1 = 200,000 B/s**，是这个方案的最低要求。

---

## 三、一组数据的结构

```
┌────────────────┬──────────────┬────────────────┐
│ 波形帧 4140 B  │ 锁相帧 128 B │ 频谱帧 4144 B  │  共 8412 B
│  V32CAP3!      │  V32MEAS!    │  V32SPEC!      │
└────────────────┴──────────────┴────────────────┘
```

三帧**各自独立 CRC32**，任一 CRC 错则该帧作废，不影响其它两帧。
频谱帧用 `wave_frame_id` 关联到同组的波形帧（和锁相帧的做法一样）。

> ⚠️ 频谱帧对应的 FFT **应当与分析窗口是同一段采集**（至少紧邻），
> 否则屏幕上「波形」和「频谱」对不上，用户会以为仪器坏了。

---

## 四、频谱帧 V32SPEC! 格式

| 偏移 | 长度 | 字段 | 类型 | 取值 / 说明 |
|---|---|---|---|---|
| 0 | 8 | `magic` | char[8] | `V32SPEC!`（`56 33 32 53 50 45 43 21`） |
| 8 | 4 | `version` | u32 | **1** |
| 12 | 4 | `length` | u32 | 整帧字节数 = `44 + bins + 4` |
| 16 | 4 | `wave_frame_id` | u32 | 关联的波形帧 `frame_id` |
| 20 | 4 | `result_id` | u32 | 结果序号，每帧 +1 |
| 24 | 4 | `nfft` | u32 | FFT 点数，**8192** |
| 28 | 4 | `bins` | u32 | 本帧携带的 bin 数，**4096**（正频率半边） |
| 32 | 4 | `fs_eff_hz` | u32 | 等效采样率 = `65000000 / decimation` |
| 36 | 4 | `window` | u32 | 0=Hann 1=Blackman 2=Flat Top（实际用的窗，回报给主机） |
| 40 | 4 | `scale_dbfs` | u32 | 幅度标度，**120**（见第五节） |
| 44 | `bins` | `spectrum` | u8[bins] | bin 0..bins-1，**每 bin 1 字节** |
| 44+`bins` | 4 | `crc32` | u32 | 覆盖前面全部字节（不含自己） |

**bins = 4096 时整帧 4144 字节。**

### bin 序号与频率的对应

```
f(k) = k × fs_eff_hz / nfft        （k = bin 序号）
```

例：fs_eff = 65 MHz、nfft = 8192 → 每个 bin = **7.9346 kHz**，
bin 3781 ≈ **30.00 MHz**。

---

## 五、幅度编码（每 bin 1 字节）

```
byte = round( (dBFS + scale_dbfs) / scale_dbfs × 255 )      钳位到 0..255
dBFS = byte / 255 × scale_dbfs - scale_dbfs
```

- `scale_dbfs = 120` → 0 = **−120 dBFS**，255 = **0 dBFS**，分辨率 **0.47 dB**
- dBFS 参考与现有实现一致：**满刻度 2048 码（peak）= 0 dBFS**
  ```
  dBFS = 20 × log10( 幅度码 / 2048 )
  ```

> 为什么只用 1 字节：屏幕一格才几个像素，0.47 dB 已经远超显示需要；
> 用 2 字节会让整组变成 12460 B、帧率掉到 16 组/秒。

---

## 六、窗函数命令（主机 → FPGA）

复用现有的**反向通道**（主机 TX → FPGA RX）。命令固定 2 字节：

| 命令 | 含义 |
|---|---|
| `0xA5, k` | 抽取倍数 = 2^k（k=0..8）——**已有** |
| `0xA6, w` | **窗函数 w**：0=Hann，1=Blackman，2=Flat Top ——**新增** |

FPGA 收到 `0xA6` 后，把下一次 FFT 的窗换掉，并在后续频谱帧的
`window` 字段里填**实际使用的窗**（主机靠这个字段确认生效）。

默认上电用 **Hann**（与现有片上找频一致）。

---

## 七、验收标准

1. **回归**：波形帧、锁相帧格式和现在**完全一致**（偏移、长度、CRC 都不变）。
2. **帧率**：2 Mbaud 下三帧连续发送，主机实测 **≥ 22 组/秒**。
3. **频谱正确性**：输入 30 MHz、1 Vpp 正弦，
   - 频谱帧里 **bin 3781** 应是最大值
   - 该 bin 的 dBFS 与主机示波器读到的幅度能对上（±1 dB 内）
4. **窗函数**：主机发 `A6 01`（Blackman）后，
   后续频谱帧 `window` 字段应变成 1，且主瓣明显变宽（这是窗生效的证据）。
5. **关联**：频谱帧的 `wave_frame_id` 必须等于同组波形帧的 `frame_id`。

## 八、示例文件（可直接逐字节对照）

| 文件 | 内容 |
|---|---|
| `sample_1_wave.bin` | 波形帧 4140 B（30 MHz 正弦，1024 点） |
| `sample_2_meas.bin` | 锁相帧 128 B（`usable=1`，30.000 MHz，相位差 21.97°） |
| `sample_3_spec.bin` | **频谱帧 4144 B**（8192 点 FFT 的结果，峰值在 bin 3781） |
| `sample_4_group.bin` | 上面三帧按顺序拼成的一组，**8412 B** |

### `sample_3_spec.bin` 前 48 字节

```
00000000  56 33 32 53 50 45 43 21 01 00 00 00 30 10 00 00  V32SPEC!....0...
00000010  e9 03 00 00 f4 01 00 00 00 20 00 00 00 10 00 00  ......... ......
00000020  40 d2 df 03 01 00 00 00 78 00 00 00 35 35 35 35  @.......x...5555
```

第 16 字节起的 `01 03 00 00` 是 `wave_frame_id`（这里 = 1001），
第 36 字节 `01 00 00 00` 就是**窗函数 = Blackman**。

## 九、自检

```bash
python check_v32_frame.py 抓包.bin
```

会逐帧打印类型、关键字段、CRC 和频谱峰值位置：

```
[V32CAP3!] fid=1001 pts=1024 CRC OK
[V32MEAS!] wid=1001 usable=1 amp1=300.0 counts pdiff=21.97° CRC OK
[V32SPEC!] wid=1001 nfft=8192 bins=4096 win=Blackman 峰值 bin 3781 = 30.00 MHz CRC OK
```

**跑不出这三行，就说明还有问题。**
