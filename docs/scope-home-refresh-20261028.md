# 示波器主页与刷新优化（2026-10-28）

用户指定目标是 Linux 屏幕上的示波器主页。保留 RAW 点数、min/max 峰值保留、抗锯齿、重建滤波器和测量算法，未改 FPGA bit、UART 帧格式、三窗函数和解调判决。

## 界面参考

通过 GitHub 插件检索和读取原项目资料，参考界面分区与信息层级，未引入这些项目的代码或依赖：

- [ScopeGUI](https://github.com/shuai132/ScopeGUI)：简洁的示波器工作区、通道识别与频谱入口。其文档60FPS是该项目自己的描述，不是本板目标或实测指标。
- [Sparrow Extended UI](https://github.com/mriscoc/Sparrow-Extended-UI-for-RIGOL-DHO800_DHO900)：紧凑状态栏、测量栏重组、通道控件、暗底布局。
- [ngscopeclient](https://github.com/ngscopeclient/scopehal-apps)：专业信号分析客户端资料，未移植其桌面/Vulkan运行时。

本机改成深蓝背景、低对比网格、青色CH1/黄色CH2，顶部标明65 MSPS与采集/显示状态。默认隐藏未启用的七项光标读数；开启光标后保留主测量并展示光标细节，避免右栏越界。全屏、导航与原有触摸控制保留。

## 刷新与正确性

- 主循环调度100ms改为33ms；LVGL显示周期保持33ms。
- 文本相同不再反复分配并使整块面板失效。
- 未改变的触发线、触发电平、隐藏迹线、光标、绘图模式不再重复要求重绘。
- 修正迹线仅颜色/线宽/显隐改变时没有重绘的问题；刻度文字变化即使个数不变也要重绘。
- 顶栏分别显示 `RAW .../s`（CRC正确到帧数）与 `UI ...fps`（实际DRM翻页数），暂停明确标记PAUSED。界面翻页不等于新采样帧。
- 原ANA处理32帧/20ms软预算保留，防止持续收帧抢占整个UI循环。

## 本板测量

rk3506、1024×600 @49Hz、UART2Mbaud。相同1MHz正弦发生器设置，在同一板上分别运行备份版与候选版，每段正常运行5秒：

| 指标 | 备份版 | 新版 |
|---|---:|---:|
| 正常运行DRM显示刷新 | 10.0 FPS | 22.9 FPS |
| 新版RAW实际到帧 | — | 20.12帧/秒 |

另一次无改发生器状态的4秒窗口，新版26.2FPS、RAW20.0帧/秒。短时测量受输入、页面操作与显示负载影响；不能承诺所有页面都达到相同帧率，更不是65MSPS数据全部经过串口送屏。

候选版强制重绘测试现显式使整个屏幕失效，因此全屏重绘16.1FPS与旧版只依赖控件失效的21.8FPS不是同等工作量，**不作为前后性能对比**。性能结论只取相同正常运行模式。

发生器原设置已回读恢复（测试前CH2输出关闭）；不会为展示截图永久打开输出。
