# BPSK 启动期擦除定位

已有45°/225° GUI日志的3次累计擦除在首条记录（PN7未锁、检查数0）之前已经产生；之后41秒无新增擦除，PN7检查42329次零错。同一份后续真实抓包从32个帧位置启动CLI均无擦除，不能据此唯一解释GUI启动瞬态。

## 同一串口读者记录实际输入

仅定位时启用，默认关闭：

```
WAVE_RAW_CAPTURE=/tmp/bpsk_start_unique.bin BPSK_TRACE=1 WAVE_MEASDBG=1 \
  waveform_demo --source uart:/dev/ttyS1 --view mod --baud 2000000 \
  >/tmp/bpsk_start_unique.log 2>&1
```

停止守护并确认只有这一个串口读者。路径必须不存在，不能使用旧文件或复用固定文件名。无需第二个cat/串口抓包程序，也不应开第二个GUI。

- UART读线程复制自己收到的字节到1MiB有界队列，独立线程写盘，读线程不执行磁盘I/O。
- 最大记录8MiB；容量上限后保留连续前缀，不继续拼接后续片段。队列溢出同样停止于前缀，并报告overflow=1；不能将其作为完整事件捕获。
- 文件创建失败明确记录错误，正常UART解析继续。
- 结束使用SIGTERM（普通kill），不要用SIGKILL/kill -9。正常退出会停止读线程、排空记录队列并输出`[rawcap] finished`。
- 检查`accepted==written`、`overflow=0`、`error=0`。limit=1表示8MiB截断；没有finished行不能声称已完整排空。
- `BPSK_TRACE=1`只增加擦除事件诊断；算法、阈值与计数不变。

## 事件日志

每次擦除记录`[bpsk-erasure]`：cfg/fid、已恢复符号数、擦除前累计数、PN7锁定前状态、有效参考检查数、I/Q、EVM，以及原因：

- `window_qualification`：已有候选锁定后，窗口资格失效。
- `symbol_threshold`：窗口合格，但当前符号I幅度或Q分量不满足现有判决门限。

需要结合该事件所在ANA帧的原始数据重放，不能仅凭一次EVM或截图归因模拟前端、FIR或载波环。

## 实测步骤

先等发生器读回45°/225°、1MHz、1000Bd PN7的有效阶段号。固定配置mode6/ch0/R4096/DDC1MHz，确认回显后启动上述记录实例。明确本地1000Bd、解码开、PN7开，以实际标签和日志为准。运行约20秒，保留启动至结束的完整日志；如未复现，可在同一固定源下重新启动记录实例或重新启用解码，每次用不同文件名，最多三个片段。不要清零或隐藏擦除数来凑“通过”。

上传每个bin、完整日志、操作时刻及真实截图；由电脑使用同核心CLI重放：

```
BPSK_TRACE=1 bpsk_capture_decode capture.bin 1000 1 0 bits.txt >decode.json 2>events.log
```

如果GUI出现擦除而同输入CLI没有，继续按GUI实际重置时刻/帧号对齐重放；两个程序不能使用不同起点却直接比较。
